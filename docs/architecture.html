🛡️ Voice Clone Shield

Architecture, Tech Stack, and End-to-End Intelligence Pipeline for Smart India Hackathon

Tech Stack & Models

Backend Framework

FastAPI (Python 3.11): High-performance async API server handling audio processing, routing, and WebSockets.

Deepfake / Voice Detector

AASIST-L (PyTorch): Pretrained state-of-the-art anti-spoofing model for zero-shot deepfake voice detection running on CPU.

Speech-to-Text (ASR)

IndicConformer / faster-whisper: Multilingual ASR optimized for Hindi and Marathi transcription to generate text from speech chunks.

Scam Detection Rule Engine

Rule-based Heuristics: NLP pattern matching for urgency, OTP/PIN sharing, bank impersonation, and threat vectors.

Frontend Dashboard

Flutter (Dart): Cross-platform application connecting to the FastAPI backend to visualize threat timelines and history.

Storage & Data

SQLite: Lightweight local database for persisting session history, analysis results, and threat events.

System Dataflow

The end-to-end pipeline processing raw audio into a fused risk assessment and actionable threat warnings.

Execution Workflow

  • 1. Ingestion & Preprocessing

    Audio is captured via the Flutter app (or uploaded) and sent to the FastAPI backend. The AudioProcessor validates the format, converts it to 16 kHz Mono, normalizes the volume, and splits it into 1-second chunks for analysis.

  • 2. Voice Deepfake Analysis

    The acoustic chunks are passed into the AASIST-L PyTorch model. It extracts spectral features and calculates the probability of the audio being a "bonafide" (real) human voice versus an AI-generated clone/spoof.

  • 3. Transcription (ASR)

    Simultaneously, the audio is routed to the IndicConformer or faster-whisper engine. It transcribes the spoken Hindi or Marathi audio into text, handling code-mixed languages when possible.

  • 4. Scam Detection

    The generated transcript is fed into the ScamDetector. It scans the text against an extensive rule-set identifying keywords related to impersonation (police, bank), urgency, secrecy, and financial requests (OTP, PIN).

  • 5. Risk Fusion

    The RiskEngine combines the scores using a transparent weighted formula (e.g., 40% Voice Risk, 40% Scam Risk, 20% Context). It calculates a final risk score from 0 to 100 and assigns a tier: LOW, MEDIUM, or HIGH.

  • 6. Liveness Challenge (High Risk Only)

    If the Risk Tier hits HIGH, the system issues a dynamic, text-based Liveness Challenge via the LivenessService (e.g., asking the user to repeat a specific random phrase) to defeat automated cloning bots.

  • 7. Threat Warning & Dashboard

    The final unified AnalysisResponse is returned to the Flutter client, displaying real-time visual warnings, granular scam indicators, and logging the event in the local SQLite threat history database.
